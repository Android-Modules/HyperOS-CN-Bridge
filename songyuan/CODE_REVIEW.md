# 3.1 系列代码复核

运行时复核范围：安装器、组件归属表、构建与签名校验、启动前切换、解锁后恢复、下载数据库迁移、NFC UID、更新包处理、WebUI 桥接与状态、定位权限。

本轮发现并修正：

- KernelSU 的私有 umask 使动态生成的目录为 0700。APK 文件虽为 0644，系统仍无法遍历账号和 TSM 目录。准备及提交前递归固定目录 0755、文件 0644，并拒绝符号链接。
- 原状态把 next-job 与已启动的 mounted 都当作等待重启。现在只把 next-job 显示为待重启；已提交显示配置中，失败优先显示错误，完成后清除旧的 early 错误文件。
- 查找设备已有官方国行更新，定位失败来自 runtime permission 和 UID AppOps 拒绝。加入首次启用修复，保留后续用户自行修改权限的选择。整包启动验证时移除本系统不存在的 BACKGROUND_LOCATION AppOps，后台定位通过 runtime permission 授予，确认完成标记写入。
- 默认图标改从 Android PackageManager 读取已安装应用，绘制为 PNG 并按包版本缓存；WebUI 只接受 PNG data URI，无法读取时回退占位图。
- 关闭国内时钟时，除启动扫描回退 APK 外，再登记同签名国际版更新，避免随后卸载模块时丢失唯一可扫描的时钟。

已核查的关键约束：

- WebUI 不调用 reboot；save 仅准备新树与 job，手动重启前不改活动树。
- 组件和路径来自固定 catalog；配置严格验证布尔类型与完整 ID 集，拒绝未知 ID、路径越界与符号链接。
- ZIP 每个 APK 检查包名、原始签名和证书，所有组件文件再次核对 SHA256；不修改或重签 APK。
- shared dependency 按所有 owner 的实际开关决定，Global 别名遮罩及包权限随同一 unit 切换。
- data/app 更新只移动经过目录约束的单包目录；恢复 split 使用安装会话，失败放弃会话。
- NFC 仅在系统扫描前修改目标包 UID；检查共享签名并保留当次完整备份用于即时失败回退，不在日后恢复整份旧系统设置。
- 下载数据库 Global=123、CN=125；迁移副本完整性检查后等待 FBE 解锁再原子发布，避免重放旧数据覆盖版本。
- late 的数据恢复有 checkpoint，提交后才清理 previous-system 和更新 applied；失败保留现场。
- 私有备份和安装源仅 Root 可读；发布应用树使用系统可读权限。

验证记录以 VALIDATION.md 为准；页面可打开、实际下载、定位、实体卡支付与整机云恢复分别记录，不相互替代。

## GitHub 发布构建

发布流程从同一 songyuan 源码构建，根目录旧版安装脚本不参与发行。构建器支持 JAVA_HOME、PATH 和 Android SDK 环境变量，repair.jar 内部 ZIP 使用固定时间戳，未改变运行时控制器逻辑。

ROM 二进制通过独立 Release 资源提供，锁文件同时记录压缩包及逐文件 SHA256。解包拒绝非清单成员、目录穿越、链接、重复条目和大小 / 哈希不匹配；目标必须是新目录。工作流使用只读仓库权限，所用 Actions 固定到提交 SHA，输入先写入环境变量后以引号引用。SDK 命令行工具显式安装，避免依赖运行器预装的 sdkmanager。

云端执行完整 APK 签名、包名、证书、最终组件文件与 ZIP CRC 校验，以及 WebUI 浏览器测试。发布的 Artifact 仅包含模块、校验值、来源清单和构建记录，不包含私有诊断或应用数据。

## 3.1.1 相册外置目录

修复范围固定为主用户相册的 Android/data 目录，当前 UID 同时核对 PackageManager 与 DE 数据目录；不接受调用者提供的包名、路径或 UID。不遍历符号链接，检查规范路径、条目类型及硬链接，改属主前重新核对设备、inode、模式及旧 UID。先保存 Root 私有元数据记录，再使用 lchown 只改变旧 UID，保留组、文件内容与标签。发现错误时不写完成标记，后续启动可重试；无变更时不停止应用。该检查放在其他启动修复之后，避免阻止既有修复。

应用双开会创建用户 999，旧安装检查因此拒绝维护升级。新检查读取 DE 用户目录，只有已有 applied 配置、安装模式且 19 项 enabled/remove 全部不变时允许多用户升级；首次安装、WebUI 保存、组件与 UID 切换仍保留单用户限制。未删除双开空间或迁移其他用户数据。
